# AGENTS.md — HireMe

Flutter GetX recruitment platform (job seekers + companies). Firebase (Auth, Firestore, RTDB, FCM) + Supabase (auth, storage, DB).

## Required Workflow

Read the relevant skill from `hireme_skills/` **before** writing any code.

| When | Skill |
|------|-------|
| Before any new controller or feature screen | `flutter-getx-controller` |
| Before touching backend, routing, notifications, chat, auth, or uploads | `hireme-architecture` |
| Before writing or editing any test | `hireme-testing` |
| After completing work, before marking done | `flutter-code-review` |
| Before committing or opening a PR | `flutter-pr` |

**CI** (`.github/workflows/flutter.yml`): `pub get` → `analyze` → `test --no-pub` → `build apk --release` → Firebase App Distribution. Flutter `3.41.6`, Java 17. `.env` created from secrets.

### Deploy (project root only)

```
firebase deploy --only database
firebase deploy --only functions
firebase deploy --only firestore:indexes
```

Cloud Functions source: `functions/index.js` — 7 v2 handlers (4 event-driven: `onNewApplication`, `onApplicationAccepted`, `onApplicationRejected`, `onNewChatMessage`; 3 callable: `rankCandidates`, `analyzeCv`, `getJobRecommendations`), runtime Node.js 20. Callables use Groq SDK (`GROQ_API_KEY` secret, model `llama-3.3-70b-versatile`, `memory: 1GiB`, `timeoutSeconds: 120`) + Google Document AI OCR for PDF text extraction.

## Gotchas & Conventions

- **Testing:** Manual fakes only — no mockito/mocktail. Call `Get.reset()` in `tearDown` (and `setUp` if `setUp` registers any GetX controllers). No Firebase/Supabase init needed in tests.
- **Firestore:** All writes must use `SetOptions(merge: true)` — never plain `set()`.
- **Logout:** Delete FCM token from Firestore via `FieldValue.delete()`, then `deleteToken()`, then `clearAuthSession()`, then `signOut()`. Pattern in `profile_controller.dart:150-169`. Skipping any step leaks FCM tokens.
- **Notification data types:** `chat_message`, `application_update`, `new_application`. Maps to different routes in `NotificationService._navigateFromData` (lines 235-262).
- **Foreground notification suppression:** `chat_message` auto-suppressed when `currentScreen == 'chat_details'`; `application_update` / `new_application` suppressed when `currentScreen == 'notifications'` (lines 164-166).
- **Notification badges:** Stream subscriptions must have `onError` handler that resets count to 0, else a stream error kills the badge permanently.
- **Storage:** CV files go to Firebase Storage (`cv/` bucket) — required by Cloud Function `analyzeCv` (Google Document AI OCR reads from Firebase Storage). Images (profile, cover, logos, job images) go to Supabase Storage.
- **Routing:** Import only `app/routes/app_pages.dart` — `app_routes.dart` is `part of` it. Use `Routes.*` constants.
- **Unprotected routes** (no middleware): `Routes.jobSeekerSearchJobs`, `Routes.pdfViewer`, `Routes.jobsMap`, `Routes.companyMap`, `Routes.companyPublic` (intentionally public).
- **UI constants:** `AppColor`, `CustomTextstyle`, `AppString`, `Assets` — all in `lib/core/utils/`.
- **Codegen:** `lib/core/utils/app_assets.dart` is auto-generated by `flutter_assets` package. Do not edit manually.
- **Secrets/config (denied in `opencode.json`):** Do not edit `lib/firebase_options.dart`, `android/app/google-services.json`, or `.env`.
- **Auth flow:** Supabase `AuthFlowType.pkce` with `autoRefreshToken: true`.
- **Platform:** Android only. iOS/macOS/Windows/Linux files are Flutter template defaults, unused.
- **Dotenv:** `.env` must contain `SUPABASE_URL` and `SUPABASE_ANON_KEY`. `firebase_options.dart` is generated by `flutterfire configure`.
- **`geocoding` package** used only in `company_map_controller.dart` for reverse geocoding. Not used in job-seeker controllers.
- **Firebase project:** `hireme-a59e6`. RTDB rules in `database.rules.json` index chats by `jobId`, `seekerId`, `companyId`.
- **AppUserRole** enum in `lib/app/services/storage_service.dart:4` — values: `'company'`, `'jobSeeker'`.

## Entrypoint (`lib/main.dart`)

`FirebaseMessaging.onBackgroundMessage` (before `dotenv.load`) → `dotenv.load` → `Firebase.initializeApp` + `Supabase.initialize` (parallel via `Future.wait`, with `Firebase.apps.isEmpty` guard) → `Get.putAsync(StorageService)` → `Get.putAsync(NotificationService)` → `runApp`.

## Edit Profile Architecture

- **ProfileView** is read-only. No add buttons, no inline editing. Edit icon beside name navigates to EditProfileView.
- **EditProfileView** has 6 tabs via `DefaultTabController`: Basic Info, Experience, Education, Skills, Languages, Links. Accepts `{'tab': 0-5}` in `Get.arguments` to open at a specific tab.
- **EditProfileController** writes to both `jobSeekers/{uid}` and `users/{uid}` with `SetOptions(merge: true)`. After save, calls `Get.find<ProfileController>().loadProfile()`.
- **Edit profile routes** (`editProfile`, `experienceForm`, `educationForm`, `skillsEditor`, `languageForm`, `linkForm`) all have `RoleGuardMiddleware(requiredRole: 'jobSeeker')`.
- **LanguageModel** fields: `name`, `level` (Beginner/Intermediate/Fluent/Native).
- **LinkModel** fields: `type` (LinkedIn/GitHub/Portfolio/Other), `url`.
- **ExperienceModel / EducationModel** have `isCurrent` bool (default `false`).

## Architecture Patterns

- **DistanceMixin** (`lib/app/modules/job_seeker/shared/distance_mixin.dart`) reads `userPosition` from `Get.find<NotificationService>().userPosition`. Provides `jobDistances`, `getDistanceToCompany()`, `updateJobDistancesFrom()`. Used by `JobSeekerDashboardController`, `JobSeekerSearchJobsController`, and `JobsMapController`.
- **JobsMapController** registered in both `MainWrapperBinding` (for IndexedStack availability) and its own `JobsMapBinding` (for direct route navigation).
- **Google Maps:** `google_maps_flutter ^2.17.1`. Use `Marker.onTap` or `InfoWindow.onTap` — `GoogleMap` widget does **not** expose `onMarkerTapped` or `onInfoWindowTapped` callbacks.
- **JobSeekerSavedJobsController** is registered via `Get.lazyPut` in **both** `MainWrapperBinding` and `JobSeekerMyApplicationsBinding`. GetX deduplicates lazyPut, so this is safe.
- **Bottom nav (job seeker):** IndexedStack order: Profile (0), Chat (1), Home/Dashboard (2), My Apps (3), Map (4). `MainWrapperController.currentIndex` defaults to 2 (Dashboard).
- **MyApplications tabs:** 5 tabs — All, Pending, Accepted, Rejected, Saved Jobs.
- **RecommendationsController** registered lazily in `MainWrapperBinding`; `RecommendationsView` is embedded inside the dashboard view. Calls the `getJobRecommendations` callable.
- **CvAnalysis** is a standalone route (`/job-seeker/cv-analysis`) with its own binding. Separate route from the `analyzeCv` callable it calls.
