# AGENTS.md — HireMe

Flutter GetX recruitment platform (job seekers + companies). Firebase (Auth, Firestore, RTDB, FCM) + Supabase (auth, storage, DB).

## Required Workflow

Read the relevant skill from `hireme_skills/` **before** writing any code.

| When | Skill |
|------|-------|
| Before any new controller or feature screen | `flutter-getx-controller` |
| Before touching backend, routing, notifications, chat, auth, or uploads | `hireme-architecture` |
| Before writing or editing any test | `hireme-testing` |
| After completing work, before marking done | `flutter-code-review` |
| Before committing or opening a PR | `flutter-pr` |

## Commands

```
flutter pub get
flutter analyze --no-fatal-infos --no-fatal-warnings   # exact flags — must match CI
flutter test --no-pub                       # matches CI; omit --no-pub locally if needed
flutter test test/<file>.dart               # single file
flutter run
flutter build apk --release
```

**CI pipeline** (`.github/workflows/flutter.yml`): `pub get` → `analyze` → `test --no-pub` → `build apk --release` → Firebase App Distribution. Flutter `3.41.6`, Java 17. `.env` created from secrets in CI.

### Deploy (project root only)

```
firebase deploy --only database
firebase deploy --only functions
firebase deploy --only firestore:indexes
```

Cloud Functions source: `functions/index.js` — 6 v2 handlers (4 event-driven: `onNewApplication`, `onApplicationAccepted`, `onApplicationRejected`, `onNewChatMessage`; 2 callable: `rankCandidates`, `analyzeCv`), runtime Node.js 20. Callables use Groq SDK (`GROQ_API_KEY` secret) + Google Document AI OCR.

## Gotchas & Conventions

- **Testing:** Manual fakes only — no mockito/mocktail. Call `Get.reset()` in `tearDown` (and `setUp` if `setUp` registers any GetX controllers). No Firebase/Supabase init needed in tests.
- **Firestore:** All writes must use `SetOptions(merge: true)` — never plain `set()`.
- **Logout:** Delete FCM token from Firestore via `FieldValue.delete()`, then `deleteToken()`, then `clearAuthSession()`, then `signOut()`. Skipping any step leaks FCM tokens. Pattern in `profile_controller.dart:800-811`.
- **Notification data types:** `chat_message`, `application_update`, `new_application`. Maps to different routes in `NotificationService._navigateFromData` (lines 204-230).
- **Notification badges:** Stream subscriptions must have `onError` handler that resets count to 0, else a stream error kills the badge permanently.
- **Storage:** `firebase_storage` in `pubspec.yaml` is **unused** — all uploads go through Supabase Storage.
- **Routing:** Import only `app/routes/app_pages.dart` — `app_routes.dart` is `part of` it. Use `Routes.*` constants.
- **Protected routes** use `RoleGuardMiddleware`. `Routes.jobSeekerSearchJobs` and `Routes.pdfViewer` have **no** middleware (intentionally public). `Routes.COMPANY_MAP` also has no middleware.
- **UI constants:** `AppColor`, `CustomTextstyle`, `AppString`, `Assets` — all in `lib/core/utils/`.
- **Codegen:** `lib/core/utils/app_assets.dart` is auto-generated. Do not edit manually.
- **Secrets/config (denied in `opencode.json`):** Do not edit `lib/firebase_options.dart`, `android/app/google-services.json`, or `.env`.
- **Auth flow:** Supabase `AuthFlowType.pkce` with `autoRefreshToken: true`.
- **Platform:** Android only. iOS/macOS/Windows/Linux files are Flutter template defaults, unused.
- **Dotenv:** `.env` must contain `SUPABASE_URL` and `SUPABASE_ANON_KEY`. `firebase_options.dart` is generated by `flutterfire configure`.
- **`geocoding` package** used only in `company_map_controller.dart` for reverse geocoding. Not used in job-seeker controllers.

## Entrypoint (`lib/main.dart`)

`FirebaseMessaging.onBackgroundMessage` (before `dotenv.load`) → `dotenv.load` → `Firebase.initializeApp` + `Supabase.initialize` (parallel via `Future.wait`, with `Firebase.apps.isEmpty` guard) → `Get.putAsync(StorageService)` → `Get.putAsync(NotificationService)` → `runApp`.

## Architecture Patterns

- **DistanceMixin** (`lib/app/modules/job_seeker/shared/distance_mixin.dart`) provides `userPosition`, `jobDistances`, `getDistanceToCompany()`, `updateJobDistancesFrom()` to any controller. Used by `JobSeekerDashboardController`, `JobSeekerSearchJobsController`, and `JobsMapController`. Distance values are consumed by `JobCardWidget` via `distance` parameter.
- **JobsMapController** registered in `MainWrapperBinding` (not its own `JobsMapBinding`) because the map lives inside the IndexedStack, not as a separate route. The `JobsMapBinding` file exists but is unused.
- **Google Maps:** `google_maps_flutter ^2.17.1`. `GoogleMap` widget does **not** expose `onMarkerTapped` or `onInfoWindowTapped` callbacks. Use `Marker.onTap` or `InfoWindow.onTap` instead.
- **Sort by distance:** `sortByDistance` observable toggle exists in both `JobSeekerDashboardController` and `JobSeekerSearchJobsController`. Sort only activates when `userPosition.value != null`. Jobs with `null` distance (no coordinates) sort last.
- **`JobSeekerSavedJobsController`** is registered via `Get.lazyPut` in **both** `MainWrapperBinding` and `JobSeekerMyApplicationsBinding`. GetX deduplicates lazyPut, so this is safe but non-obvious.
- **MyApplications tabs:** 5 tabs — All, Pending, Accepted, Rejected, Saved Jobs. Saved Jobs uses `JobSeekerSavedJobsController` with `JobCardWidget`.
- **Bottom nav (job seeker):** IndexedStack order: Profile (0), Chat (1), Home/Dashboard (2), My Apps (3), Map (4). `MainWrapperController.currentIndex` defaults to 2 (Dashboard).
- **`JobCardWidget`** accepts `distance` (double?) for displaying km from user. Shared across dashboard, search, and saved-jobs views.
